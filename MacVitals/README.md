# MacVitals

原生 macOS 菜单栏系统监控应用，支持 macOS 13 及以上版本。普通指标无需第三方依赖或管理员权限；CPU/GPU 频率与芯片功耗需要安装管理员采集服务。

## 使用

本机已安装到 `/Applications/MacVitals.app`。双击“应用程序”中的 MacVitals，菜单栏使用 13 点半粗等宽字体，仅显示下载和上传速度，例如 `↓28K ↑3K`；CPU、内存等指标在点击打开的完整面板中查看。两个速率字段使用固定宽度和等宽字体，数字、单位变化时箭头与相邻图标保持原位，悬停可查看完整说明。顶栏网速使用整数及 B/K/M/G 单位（字节/秒），面板和悬浮提示保留小数；文字颜色跟随系统菜单栏，保证深浅背景下可读。点击打开深色监控面板，点击外部、切换应用或按 Esc 即关闭。CPU、内存、风扇、温度使用两列遥测仪表：CPU 分段环形表、内存容量块、风扇转速指针、温度热度刻度，数值采用高对比文字。底部历史强度条支持最近 30 秒、1 分钟或 2 分钟切换，显示各时间段的平均采样强度。网络面板使用镜像流量柱，上半区蓝色下载、下半区橙色上传；下方提供电池分段电量仓（充电时显示闪电标识）、磁盘容量块（亮色为已用容量，大字为可用空间）及交换空间，页脚固定显示运行时间和详情入口。曲线持续采样，历史只保存在内存中，退出后清空。风扇显示最高转速；缺失数据用破折号与状态说明表示。面板高度根据屏幕可用空间调整，小屏幕可滚动。

在菜单中启用“登录时启动”即可随登录启动。自行构建后请将 `dist/MacVitals.app` 复制到 `/Applications` 再运行。如果系统要求批准，请在系统设置 → 通用 → 登录项中允许。首次 CPU 采样显示省略号，下一次刷新后显示利用率。

CPU、内存、网速固定每 2 秒采集；设置菜单显示该间隔，退出也在菜单内。应用不显示 Dock 图标。

## macOS 原生小组件

macOS 14 及以上可使用 WidgetKit 原生小组件。安装后启动一次 MacVitals，在桌面空白处右键 →「编辑小组件」，搜索 MacVitals，选择「网速」或「系统状态」。网速提供小号和中号，显示下载、上传；系统状态提供小号、中号和大号，小号显示 CPU、内存，中号和大号还显示网速。点击组件打开完整监控面板。

中号与大号「系统状态」采用终端风格的四格仪表：淡黑绿网格、等宽数字、CPU / MEM / RX / TX 标签与采样时间。CPU、内存使用固定 0–100% 环形仪表；下载以青色、上传以琥珀色区分，使用最近 60 秒的历史柱条，中号 12 格、大号 30 格，每格取该时间段的真实采样峰值，缺失时间段留空。最多保留最近 60 秒、32 次采样。网速纵轴按 1/2/5 档位缩放，减少每次按精确峰值重新缩放的跳变。数字、仪表和柱条配置 0.35 秒原生过渡，固定标签与采样时间不使用默认模糊过渡，并遵守「减少动态效果」设置。采样仍为离散更新，实际过渡由 WidgetKit 播放，不提供持续动画或伪造中间采样。数据过期显示 STALE，无数据时显示 NO DATA。外观预览可运行 `scripts/preview-widgets.swift`（与 `TelemetryWidgetView.swift`、快照和格式化源文件一起编译）。

设置里的「仅显示小组件（隐藏顶栏）」可隐藏网速和 Agent 顶栏项，主程序继续后台采样。点击桌面组件可打开独立的监控与设置窗口，取消该选项即可恢复顶栏。隐藏顶栏不等于退出 MacVitals：原生组件可独立显示，但实时数据仍依赖主程序；退出后保留历史快照，停止产生新采样。

小组件显示最近采样的快照与采样时间，超过两分钟标记「历史采样」；没有采样时显示「尚未采样」。主应用每 2 秒原子保存 CPU、内存与网速快照，并请求更新组件；原生组件实际更新仍由 macOS 调度，可能合并或延后请求。组件自身每 15 分钟请求一次后备更新，以便主应用停止时标记历史数据。这台 Mac 已实际响应秒级请求，但不代表所有系统状态、版本与设备都能维持相同速度。

快照包含 CPU、内存、网速、接口名称、时间和有上限的短期历史数据，扩展以沙盒只读权限读取 `~/Library/Application Support/MacVitals/widget-snapshot.json`。应用退出后组件可保留历史快照。

刷新实测：用 `open /Applications/MacVitals.app --args --widget-refresh-probe 1` 启动一秒采样和请求模式，`--widget-refresh-probe` 支持 1、2、5、10、30、60、300 秒请求间隔；采样在探测模式下一律为一秒，不写入用户刷新偏好。使用 `/usr/bin/log stream --level debug --style ndjson --predicate 'subsystem == "local.macvitals.monitor" AND category == "widgetProbe"'` 记录主程序请求与扩展真实回调，用 `python3 scripts/analyze-widget-probe.py <日志文件>` 统计间隔及数据年龄。关闭后正常启动应用即结束探测。


## Agent Monitor

另有独立的终端图标顶栏项，使用 13 点半粗字体显示当前本地 agent 实例数量。Agent 卡片提供明显的“打开神经网络”按钮，可从顶栏下拉面板直接打开独立神经网络窗口；关闭弹窗不会关闭该窗口。点击查看 CPU、RSS 内存、磁盘读写速率、CPU 点阵历史及可展开的子进程列表。界面采用扫描线、六角节点、硬边框和终端等宽字体，Codex 与 Claude Code 使用独立配色；点阵历史采用对数刻度增强低占用可见性，数值仍显示真实百分比。支持 Codex、Claude Code、Gemini CLI、OpenCode、Cursor 和 Aider。两个顶栏项可以分别按住 ⌘ 拖动，macOS 管理初始顺序和位置记忆。

Agent 模块使用独立的采样器、后台队列、弹窗和 2/5/10 秒刷新设置，不改变原系统监控的采样、面板或管理员服务。实例按本地应用或 CLI 进程树识别，不代表会话数量或正在执行任务；只读取当前用户的可访问进程。CPU 以单核心 100% 计，多核使用可能超过 100%；RSS 为子进程合计，共享页可能重复计算。缺失指标显示破折号，新进程先建立计数基线。识别仅保留可执行文件和必要的脚本入口，不保存完整命令参数、提示词或环境变量。

卡片上的「结束」菜单与详情、神经网络窗口顶部的「结束实例」可结束当前实例；详情中选中节点后的「结束此进程」仅针对该节点。提供「结束…」（SIGTERM）与「强制结束…」（SIGKILL），均先显示名称、PID 和影响范围供确认，取消不会发送信号。整个实例操作只使用确认时列出的关联进程，先子进程、后根进程；确认后新增的进程不自动加入范围。执行前重新读取当前用户的进程身份与父子关系，每次发送信号前核对 PID、启动时间和 UID，跳过已退出、身份变化或离开该实例的进程，不发送进程组信号，也不使用管理员权限。未退出的进程可再次选择强制结束；不会自动升级为 KILL。界面显示已发送、跳过和失败数量，随后按实际采样反映退出状态。桌面 Agent 实例包括应用进程，结束实例可能退出整个桌面应用。

每张 Agent 卡片提供“详情”按钮，打开可调整大小的独立窗口，实时展示启动时间、运行时长、PID/PPID/UID、左侧可交互进程节点网络与右侧节点检查器、可执行路径、脚本入口、BSD 状态、线程/运行线程/优先级、RSS/物理足迹/虚拟内存、累计用户/内核 CPU 时间、磁盘累计读写与速率、缺页/页入/上下文切换计数。详情采用神经网络视觉：根进程居中，子进程环绕分布，节点大小随 RSS 内存变化，CPU 光环以单核 100% 为满环，活动粒子仅在采集到 CPU 活动时显示；连线只表示父子进程。蓝紫节点配色、顶部四路资源仪表和最近 120 秒历史保持实时采样。支持点击节点、搜索、列表切换与多进程分页。详情使用系统字体和柔和圆角卡片。神经图支持按钮放大/缩小（100%–350%）、聚焦选中节点、复位、拖动平移、触控板捏合缩放，点击详情中的神经图空白区域、任意节点或独立窗口按钮，会打开可调整大小、最小化和全屏的“神经网络”专用窗口，并选中所点进程。专用窗口支持逐节点查看身份、资源与内核指标、搜索、列表切换，以及展开画布/恢复双栏布局；系统减少动态效果设置会停止动画。点击节点或节点标签会选择对应进程；即使画布已展开，也会自动恢复详情栏。节点命中检测与画布使用一致的缩放和平移坐标。右侧按身份、资源、内核计数分组；历史图按窗口峰值自动缩放。支持搜索进程和路径、选择复制数值。退出后保留最后快照并标注；进程读取失败时保留快照并标注失败。尚未接入任务、会话、模型、Token、费用及单进程网速。

开发诊断：`.build/release/MacVitals --agents-diagnose`；预览窗口：`open dist/MacVitals.app --args --preview-agents`。

主面板的网络卡片显示当前统计网卡的本机 IPv4 / IPv6 地址，随网络切换更新。地址可选择复制，也可点击旁边的复制按钮复制该协议的全部地址；未分配时明确标注。完整接口与地址列表可在“系统详情”中查看。

## 详情

点击顶栏图标 → 面板页脚“系统详情”，打开可调整大小的系统详情窗口。分组可展开或折叠，默认展开系统、内存、磁盘、电池、风扇和 GPU。关闭窗口后可再次打开。详情支持按指标名或数值搜索、全部展开/收起，以及复制数值。

详情每 5 秒在后台采样，包含：

- 系统、芯片、核心数、CPU 用户/系统占用、负载均值、热状态。
- 内存页分类、压缩器占用、文件缓存、交换空间和内存压力。
- CPU/GPU/内存/电池/存储温度候选与其他温度键；只有合理的正温度读数会展示。候选分组不证明物理位置，M5 的 Tp00 名称参考 Stats 和 iSMC 映射。
- 各活动网络接口的 IPv4 / IPv6（含作用域）、上传下载速度和系统接口计数。物理和虚拟接口可能统计同一流量，不宜相加；使用系统 64 位接口计数；计数器重置或接口更换后先重新建立基线，不显示虚假峰值。
- 主目录卷的空间、全部 IOBlockStorageDriver 的累计读写和速度。
- 电池循环次数、容量、健康估算、电压、电流、电池侧功率估算和系统剩余时间估算。健康值采用满充容量/设计容量，新电池可能超过 100%，不等同于系统设置显示的健康百分比。
- 每个风扇的当前/最低/最高转速，以及驱动提供的 GPU 利用率。
- 可读取进程的 CPU 与驻留内存前五名。进程 CPU 以单核心 100% 计，与顶栏全部核心归一化利用率口径不同。

管理员采集服务已经接入 CPU/GPU 有效频率与 CPU/GPU/ANE 功耗，另有无需管理员权限的每核 CPU 利用率。功耗是系统估算，频率为采样期间的活跃有效频率；休眠核心可能显示 0 或无活跃频率。CPU+GPU+ANE 合计不等同于整机功耗。电池侧功率是电压×电流估算，不是芯片功耗。

### 管理员采集服务

可选安装 `local.macvitals.power` LaunchDaemon，约每 5 秒执行一次固定参数的系统 `/usr/bin/powermetrics`，采集 1 秒窗口。只有检测到 MacVitals 进程时才执行实际采样；退出应用后不再调用 powermetrics。服务会随系统启动恢复。

- 服务配置：`/Library/LaunchDaemons/local.macvitals.power.plist`
- 只读采集脚本：`/Library/PrivilegedHelperTools/local.macvitals.collect-power.sh`
- 最新结果：`/var/run/local.macvitals.power/sample.plist`，原子替换，仅保留一份，不持续增长。
- 上述采集脚本及输出目录由 root 所有，应用只读取数据，不以 root 身份运行。没有全局免密 sudo 设置。
- 20 秒内没有新采样时，界面显示读数已过期，不继续显示旧功耗。

安装：在项目目录下的终端运行 `sudo /bin/sh scripts/power/install.sh`。若 macOS 阻止访问 Downloads，可先将 `scripts/power` 整个目录复制到 `/private/tmp` 后运行其安装脚本。

卸载管理员服务：运行 `sudo /bin/sh scripts/power/uninstall.sh`（受 Downloads 权限限制时，同样先复制脚本到 `/private/tmp`）。卸载后普通 CPU、内存、温度、网络等监控仍可使用，频率与功耗显示等待采集。

使用 `.build/release/MacVitals --details-diagnose` 可输出详情快照。温度/进程/接口列表只有当前可读取的项，详情历史不写磁盘。

## 构建

安装 Apple Command Line Tools 后执行：

```sh
./scripts/build.sh
open dist/MacVitals.app
```

脚本生成当前 Mac 架构的 Release 应用并进行本地 ad-hoc 签名。此签名用于本地运行，分发给其他用户需要 Developer ID 签名和公证。

## 诊断

```sh
.build/release/MacVitals --diagnose
```

诊断模式采样一次后输出实际指标并退出，不启动菜单栏界面。

使用 `.build/release/MacVitals --sensors` 可只读枚举所有 SMC 键及温度候选读数。枚举结果输出到终端，需要时可自行重定向保存。键名不能独立证明具体物理传感器的位置。

## 刷新与采集开销

CPU、内存、网速、温度和风扇按所选刷新间隔更新，默认 2 秒。电池状态与硬盘容量每 15 秒刷新；打开系统面板或详情时立即更新这两项。系统详情只在窗口打开且未最小化时每 5 秒采集，关闭或最小化后暂停；重新打开会重建速率基线，避免把离线期间的平均速度当成当前速度。

Agent 每轮先读取当前用户进程的身份和父子关系，再对识别出的 Agent 及其子进程读取资源数据。路径与识别结果按 PID＋启动时间缓存；进程改名会触发刷新，Node/Python 脚本入口和通用 `agent` 可执行文件每轮检查，其他路径最多缓存 30 秒。新进程的发现频率保持不变。`--agents-diagnose` 同时输出发现数、元数据读取数和详细资源读取数。

## 指标口径与限制

- CPU：两次 Mach CPU ticks 的差值，所有核心整体利用率。
- 内存：活动页 + wired 页 + 压缩器实际占用 − 可回收活动页的估算，除以物理内存。并非内存压力，也不保证与活动监视器完全一致。
- 交换空间：系统 `vm.swapusage` 的已使用字节数；未使用时显示“0 B（未使用）”，详情列出当前分配量。
- 主面板网速：单个主要物理接口的下载/上传字节增量，避免 VPN 与物理接口重复计数；默认每 2 秒更新，K/M/G 使用十进制字节单位。
- 磁盘：用户主目录所在卷的容量及系统报告的可用于重要用途的空间（可能包含可清理空间）。
- 电池：IOKit 电源信息；桌面 Mac 没有电池时显示不可用。
- 风扇：只读 AppleSMC 的 `FNum` 和 `F*Ac`，支持 fpe2 / float 转速数据；0 RPM 是有效读数。无风扇或系统未开放时明确显示相应状态。
- 温度：尝试有限的 CPU 相关 SMC key，并在读数旁标明实际 key；不同机型的传感器含义和可用性不同。尤其 Apple Silicon 机型不保证可获取温度。

SMC 是非公开硬件接口，不保证所有机型或未来系统兼容。应用不会写入 SMC，也不会修改风扇控制。

## 结构

- `Sources/MacVitals/main.swift`：菜单栏 UI、刷新设置和登录启动。
- `Sources/MacVitals/SystemMonitor.swift`：CPU、内存和其他顶栏指标采样。
- `Sources/MacVitals/MetricsSupport.swift`：host 端口生命周期和设备计数增量处理。
- `Sources/MacVitals/Details.swift`：后台详情采样与分组详情窗口。
- `Sources/MacVitals/Dashboard.swift`：彩色曲线监控面板和最近两分钟历史数据。
- `Sources/CMetrics`：只读 SMC 桥接。
- `scripts/build.sh`：生成可双击启动的 `.app`。

SMC 数据包和调用约定参考公开实现：[smcFanControl](https://github.com/hholtmann/smcFanControl)、[SMCKit](https://github.com/beltex/SMCKit)。


## 回归验证

执行 `./scripts/test.sh`（仅需 Command Line Tools，无需 XCTest），覆盖进程 CPU 时间与 `getrusage` 对照、host 端口引用释放、网络计数重置/接口更换/超过 4 GiB 的统计、磁盘热插拔时忽略新设备的历史计数、缺失内存数据状态、SMC 并发关闭与读取。CPU ticks 使用无符号增量以支持计数器回绕；进程使用 PID 和启动时间识别，避免 PID 复用。

采样器持有单个 host 端口引用并在释放时归还。SMC 调用串行保护，发生传输层失败后重新建立连接并重试一次；不存在的键不会触发反复重连。网络和磁盘对当前设备集合独立保留基线，新设备从下一次采样开始统计速度。

应用图标：`assets/AppIcon.icns`；原始预览为 `assets/AppIcon.png`，可用 `swift scripts/make-icon.swift assets/AppIcon.png` 重新生成 PNG。构建脚本自动将 ICNS 嵌入应用并签名。
